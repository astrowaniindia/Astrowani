# AI CRAWLERS — ALL ALLOWED, search AND training (owner's decision, 2026-11-16).
#
# They are named in the SAME group as `*`, on purpose. A crawler that finds a
# group naming it IGNORES the `*` group completely, so a separate
# "User-agent: GPTBot / Allow: /" block would have silently dropped the
# Disallow lines below for that bot. One group = one policy for everyone.
#
#   AI search / answers (how the site gets quoted and linked in AI answers):
#     OAI-SearchBot, ChatGPT-User, PerplexityBot, Perplexity-User,
#     Claude-SearchBot, Claude-User
#   AI training (how the brand ends up in what models know):
#     GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, CCBot,
#     meta-externalagent, Amazonbot, Bytespider
#
# CLOUDFLARE OVERRIDES THIS ON shop.astrowani.com. Measured 2026-11-16: its
# "Block AI bots" setting answers GPTBot, ClaudeBot and CCBot with 403, and its
# managed robots.txt prepends "Content-Signal: ai-train=no" plus a
# "Disallow: /" group for each training bot. Until those two switches are off
# in the Cloudflare dashboard, the training half of this policy does nothing.
User-agent: *
User-agent: OAI-SearchBot
User-agent: ChatGPT-User
User-agent: PerplexityBot
User-agent: Perplexity-User
User-agent: Claude-SearchBot
User-agent: Claude-User
User-agent: GPTBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: Applebot-Extended
User-agent: CCBot
User-agent: meta-externalagent
User-agent: Amazonbot
User-agent: Bytespider
Content-Signal: search=yes, ai-input=yes, ai-train=yes
Allow: /

# Per-user pages: behind a login, different for every visitor, nothing to index.
Disallow: /wallet.html

# THE LIVE CONSULTATION SCREENS — not landing pages.
#
# An earlier version of this file said the opposite, in writing: that chat.html
# and call.html "are in fact the 'Chat with an Astrologer' / 'Call an Astrologer'
# landing pages, which carry the highest-intent keywords on the site". That was
# wrong, and the sitemap submitted both on the strength of it.
#
# Their entire text content is "Astrologer / Connecting… / Mute / Camera off /
# End chat / Billing is per minute from now". Neither has an <h1>; chat.html has
# one internal link and call.html has none. Indexed, Google could serve a page
# reading "Connecting…" for the query "chat with an astrologer".
#
# The real landing page for that intent is consult.html — <h1> "Chat with an
# astrologer", 4,200 characters — and it stays in the sitemap at priority 0.8.
# Both pages also carry <meta name="robots" content="noindex, follow"> so this
# holds even where robots.txt is not read.
Disallow: /chat.html
Disallow: /call.html

# A leftover design experiment: reachable, linked from nothing, not in the sitemap.
Disallow: /concept-hero.html
